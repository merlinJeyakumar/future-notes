### Official host-contract checks

- [Flutter's macOS integration guidance](https://docs.flutter.dev/platform-integration/macos/building) distinguishes App Sandbox entitlements from Hardened Runtime and release distribution. An app working under debug does not prove release folder access or native-library signing. The current page describes a newer Flutter release; apply its general host guidance without importing newer SDK minimums into this project's pinned baseline.
- [Apple NSWorkspace](https://developer.apple.com/documentation/appkit/nsworkspace) is the appropriate native open/reveal integration surface. Implementation must use local file URLs and report launch failures without changing attachment ownership.
- [XDG OpenURI portal](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.OpenURI.html): local files use `OpenFile` with a descriptor; the URI method does not accept `file://`. `OpenDirectory` is a separate versioned capability. This rules out treating a generic URL-launch call as sufficient Linux file integration.
- [Apple's Xcode requirements table](https://developer.apple.com/xcode/system-requirements) distinguishes the OS that runs Xcode, deployment targets, and device/simulator support. An older Intel Mac running Monterey and a supported application deployment target do not establish that the current iOS build toolchain can run there. Keep build-host and runtime minimums separate.
- [Flutter's current supported-platform page](https://docs.flutter.dev/reference/supported-platforms) explicitly describes Flutter 3.47, not the observed 3.41.5 SDK. Its current iOS/macOS floors must not silently override this project's API 24/iOS 13 requirements or trigger an unreviewed dependency upgrade.

### Acceptance gates

On macOS and Linux, validate storage admission before enabling dependent UI. Then validate multi-file picking/drop, cache cleanup/reuse, default-app opening, native reveal, library restart, window close and keyboard/IME on the actual host/package. On Android retain the accepted mobile presentation and API 31 behavior, then add API 24/current target coverage. On iOS validate hardware-keyboard semantics and native presentation only after its storage/native build blockers are fixed on Mac/Xcode. None of these host gates is proved by changing `TargetPlatform` in a Windows widget test.
