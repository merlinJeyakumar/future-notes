# HTML code editing and desktop attachments — 16 October 2026

## Implementation

- Retain the existing code editor/highlighter. Add an explicit Format HTML
  action, Consolas with monospace fallbacks, aligned line-number sizing and
  light/dark syntax themes. Rich-text to HTML conversion produces indented block
  structure in its existing worker. Opening an existing note does not format or
  rewrite it automatically.
- The formatter preserves original tags, attributes, entities, inline text and
  raw/whitespace-sensitive elements. It indents block-only structure. Incomplete
  or ambiguous nesting fails without changing source. Work runs off the UI
  isolate; typing, locking or navigation invalidates stale results. Limits are
  32 Mi characters and 256 nesting levels. It is deliberately conservative,
  rather than an HTML repair tool or JavaScript/CSS formatter.
- Pin desktop_drop 0.8.4. Dependency resolution added only that package; all
  existing locked package versions remain. Native registration files were
  generated by Flutter, not hand-edited.
- The desktop editor accepts external files as attachments, never editor HTML.
  A hover border and label appear only for an enabled current route. Locked,
  read-only, busy attachment/cutover and modal-covered notes reject drops.
- Validate all paths as regular files up to 10 GiB before first-save confirmation.
  Deduplicate repeated paths in one batch and attach sequentially through the
  existing owned worker/generation commit. First Save remains explicit. Capture
  session and credential ownership; cancellation/failure stops the remaining
  batch and retains committed attachments. No second encryption/storage path or
  whole-file attachment read was added.

## Mixed-content formatting follow-up

The user confirmed desktop file drop and the HTML code surface worked, then
reported that inline-rich paragraphs remained unstructured. The original
formatter only indented block-only trees, so a paragraph containing spans,
emphasis and repeated br elements was returned unchanged.

The renderer now structures mixed block containers and splits at explicit HTML
line breaks, including breaks nested inside inline elements. Adjacent inline
runs remain together so no word spaces are introduced. Existing literal text
spaces, tags, attributes and whitespace-sensitive elements are retained. No
personal screenshot text was copied into fixtures.

Synthetic tests compare the complete HtmlToDelta operations before/after,
including styling, adjacent words, blank lines, nested breaks, edge spaces and
idempotence. The affected formatter/widget suite passed eleven tests. An added
non-breaking-space case initially failed because the converter trims all source
line edges. The formatter now keeps Unicode edge spaces alongside their tags
and avoids splitting before intentional spaces after br. That one failed case
passed after correction; final scoped analysis reports no issues. No unchanged
storage/attachment or large-file suite was rerun.
