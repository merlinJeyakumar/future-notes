# Passes 5 and 6: data compatibility and mobile runtime

Reviewed on 2026-10-21 against the current worktree. This is source validation and a proposed repair plan; no app code was changed and no build, test, emulator or device command was run for this review. The supplied Mac audit's runtime/test counts remain its authors' observations. No user note data was inspected.

## Pass 5 — Note/package/crypto and processing compatibility

### Current source conclusions

| Check | macOS | Linux | Android | iOS |
| --- | --- | --- | --- | --- |
| Existing note/attachment formats | Shared Dart codecs available; storage integration incomplete | Shared Dart codecs available; storage integration incomplete | Same legacy format, native acceleration adapter | Same legacy format through Dart fallback; Swift adapter is not a new library cipher |
| UID decision before attachment extraction | Implemented owned-flow logic is not the ordinary legacy desktop startup path | Same limitation | Provider-owned import reaches it | Shared source exists, but fresh library admission is blocked by F6.0 |
| Four optional verification settings default off | Yes, shared settings policy | Yes, shared settings policy | Yes | Yes |
| Fast owned attachment writes | Blocked by owned desktop integration | Blocked by owned desktop integration | Native direct provider sink, otherwise encrypted transfer fallback | Deliberate encrypted transfer fallback; direct sink not implemented |
| Cache reuse, lock teardown, credential invalidation | Missing desktop native actions prevent normal file-backed cache setup | Same limitation | Shared cache plus native actions present | Shared cache plus Swift actions present; execution unvalidated |

1. **Do not change encryption formats to port storage.** `lib/core/storage/streaming_file_cipher.dart:78` identifies the existing attachment layout as 16-byte IV plus AES-SIC/PKCS7. The Android implementation explicitly preserves it (`android/app/src/main/kotlin/com/nativedevps/futurenotes/AndroidCipher.kt:31`), uses equivalent UTF-8 password truncation/padding (`:441`) and AES/CTR stream cipher (`:444`). `lib/features/dashboard/services/encryption_service.dart:48` contains the shared key derivation; the native adapter is activated only for Android (`lib/main.dart:32`). iOS/macOS/Linux retain the Dart implementation. This establishes intended byte-format agreement, not new real-host import/export proof and not a security assessment of legacy encryption.

2. **The current owned importer already inspects metadata first.** `ContentViewModel._importOwnedFile` captures the performance policy (`lib/features/dashboard/viewmodels/content_viewmodel.dart:6061`), calls `inspectPackage` (`:6146`), looks up the note ID (`:6177`), invokes the duplicate resolver (`:6196`), returns on Ignore (`:6212`), then calls bulk import (`:6241`). In `lib/features/dashboard/services/streaming_pack_service.dart:302`, `inspectPackage` is a separate bounded operation; `:1605` skips attachment records in metadata-only mode. It retains framing/ZIP-directory/metadata validation without extracting attachment payloads. `PackageImportMetadata.checkCurrent` guards source metadata around the user decision. Duplicate resolution is UID-based; it does not require comparing existing attachments. Back up & Replace checks their availability with `verifyContent: false` (`content_viewmodel.dart:6231`). Preserve this implementation and the three choices.

3. **The preceding import conclusion is not true for every current startup route.** `_usesOwnedMutations` requires `TransactionalNoteFiles.usesOwnedStorage` (`content_viewmodel.dart:735`). macOS/Linux ordinarily reach legacy FileService because owned services are Windows-gated. `importNotePack` retains a legacy fallback (`:6724`); `_importNotePack` calls buffered full extraction at `:6758`/`:6761`. Do not claim UID-before-extraction parity on those hosts just because the shared owned importer exists. Fix desktop storage integration first, then use the same owned importer rather than writing another package decoder.

4. **The requested default policy is present.** `lib/core/storage/attachment_performance.dart:3–10` defaults source checking, output verification, exported-backup validation and large-write verification to false. Missing fields are false (`:37–40`), serializers preserve explicit choices (`:63–90`), and export checks no longer force desktop verification (`:23–27`). Both desktop and mobile settings expose the switches (`lib/features/dashboard/widgets/app_settings_dialog.dart:285–324`; `lib/features/dashboard/mobile/app_settings_dialog.dart:414–455`). `test/storage/attachment_scheduler_test.dart:24` covers the shared serialized policy; its presence does not prove all platform adapters.

5. **Fast mode is ownership-dependent; do not remove ownership guards.** `StreamingFileCipher.transform` validates an owned target (`lib/core/storage/streaming_file_cipher.dart:124`); unchecked encryption/rekeying without ownership is rejected (`:148–153`). The Android equivalent requires verified or owned output (`AndroidCipher.kt:267–274`). They calculate plaintext/output digests as bytes flow (`streaming_file_cipher.dart:180–189`; `AndroidCipher.kt:279–281`). A new backend must issue receipts and validate identity, length and closure, rather than bypassing the guard or turning readback on. This retains the user's optional-check policy and accepted Windows cache exception (`lib/core/storage/attachment_open_cache.dart:352–358`).

6. **iOS intentionally has one extra encrypted transfer, not a hidden mandatory verification pass.** `lib/core/platform/mobile_library_documents.dart:23–29` reports direct sinks unsupported outside Android. `ProviderNoteFiles.createAttachmentCandidate` catches that capability result and uses private owned staging (`lib/features/dashboard/services/provider_note_files.dart:108–157`). Provider publication copies encrypted bytes while hashing that transfer (`lib/core/storage/provider_document_io.dart:156–230`); readback is conditional on the captured receipt policy (`provider_note_files.dart:442`). Android's direct sink instead adopts the owned provider candidate (`provider_generation_store.dart:176–193`). Do not require iOS native cipher work just to preserve package compatibility. Any future direct iOS sink needs coordinated held-writer semantics and its own acceptance gate.

7. **Basic format validation is not a second pass.** ZIP CRC, bounds, DEFLATE grammar and output hash are accumulated in the extraction sink (`streaming_pack_service.dart:1718–1817`); optional staged readback is conditional at `:1648`. Required provider backups and small envelope/journal revision reads remain genuine work. Provider transactions preserve attachment-first order, predecessors, version-2 guard/intent and completion acknowledgement (`provider_generation_store.dart:111–116`, `:241–315`). Recovery may read ambiguous material. Neither required transfers nor recovery reads should be described as optional full-file verification.

### Narrow proposed fixes and gates

- **P0:** Route macOS/Linux through a validated desktop-owned backend before advertising shared import/attachment guarantees. Preserve existing accepted Windows routes. Reuse codecs, metadata-only UID resolver, receipts, package streamer and journals; inject host primitives only.
- **P1:** Treat a missing receipt as a caller-contract defect at new owned call sites; do not silently re-enable verification. Internal legacy/unowned APIs may remain checked until their callers have ownership. `provider_note_files.dart:442` defaults an absent receipt to checked publication; this is an explicit legacy boundary, not evidence that the normal owned path is forced on.
- **P1:** Audit any future same-storage-ID replacement separately: `provider_note_files.dart:435` hashes an already-existing destination revision. Normal attachment/rekey/import paths use fresh IDs, so this is not evidence of an extra scan in those normal paths. Prefer fresh identity and existing predecessor journals over expanding full-file checks.
- **Acceptance:** Bidirectional Windows-1.4.1/current ↔ each actual target fixtures: protected/unprotected notes; binary/ZIP packages with/without archive password; Unicode filenames and bodies, whitespace/unknown metadata, mention IDs, duplicate/replace/ignore; changed source during the UID choice; Ignore reads zero attachment payloads; cache reuse transforms once. Record transform/necessary-transfer/readback counters with all checks off and each explicit opt-in. These are proposed development gates, not additional normal-job passes.
- **Failure gate:** interruption, cancellation, short source/write, storage full, revoked provider grant, stale identity/credential, provider rename identity change, and failed password-change commit preserve the predecessor and recoverable objects. Keep optional checks off for this testing unless a case explicitly tests opt-in.

## Pass 6 — Runtime ownership, lifecycle, background jobs and sharing

### Verified source structure and material differences

| Area | Android | iOS | macOS / Linux implication |
| --- | --- | --- | --- |
| Runtime owner | Application-retained Flutter engine and native storage/job/cipher hosts | Runner-owned Flutter controller and MobilePlatform; no second writer launched by extension | Must use desktop-owned host; do not reuse Android service or iOS controller assumptions |
| Local folder access | SAF opaque grants/descriptor leases | Security-scoped bookmarks and NSFileCoordinator | Separate filesystem primitives and desktop picker/actions required |
| Background continuation | User job foreground dataSync service, bounded wake lease, timeout/cancel coordinator | Finite UIKit background task with expiration; no scheduled BGTask runner | Desktop job lifetime belongs to process/storage owner |
| System job notifications | Per-job native notifications and cancellation routing | No native progress-notification implementation found; in-app tasks exist | Native desktop notification parity not established by mobile code |
| Library external-change/resume hints | Content observer + native resume event path | Listener is explicitly a no-op; no native equivalent channel | Desktop watchers should remain their own adapters |
| Incoming files | Manifest SEND/SEND_MULTIPLE + native lease inbox | Checked-in ShareExtension target, embed/dependency, App Group receipt inbox | macOS/Linux desktop drop/file picking need independent host wiring |
| Drafts/media/protected presentation | Platform-encrypted recovery, shared pause/teardown, Android capture policy | Keychain/AES-GCM drafts, app-switch snapshot cover, shared pause/teardown | Do not confuse native snapshot/capture settings with file encryption |

### Findings

**F6.0 — P0: iOS selected-folder admission rejects its expected collision result.** This is a current-source contract failure, independently cross-checked across caller, adapter and native implementation. First selection and library switching run `LibraryAdmissionProbe.verify` before opening/persisting the candidate (`lib/features/dashboard/views/mobile_library_startup.dart:96–97`, `:151`). The disposable probe deliberately creates an existing filename and only accepts `LibraryAccessException.code == 'name_exists'` (`lib/core/storage/library_admission_probe.dart:72–85`). `MobileLibraryDocuments._invoke` preserves the platform error code (`lib/core/platform/mobile_library_documents.dart:91–99`). Android emits `name_exists` (`LocalDocuments.kt:438`). iOS create throws a generic NSError when the file exists (`ios/Runner/MobilePlatform.swift:325`), and `reply` maps all errors to `native_document_failed` (`:70–73`). Therefore the expected successful duplicate-name rejection is rethrown as failed admission on iOS; a safe local folder cannot pass this current first-selection path. **Fix:** introduce typed Swift document errors mapped to the existing shared error codes, beginning with `name_exists`, permission/access and stale identity. Keep safe, non-sensitive messages; preserve original native error classification privately as needed. Do not relax the probe, accept every generic failure, bypass admission or fall back to private note storage. **Acceptance:** mapped native integration + actual iOS first selection, collision rejection, failed selection preserving the old library/draft, cleanup, switch and restart. This blocker outranks the later iOS parity work below.

**F6.1 — Keep the retained Android owner; do not generalize it into every platform.** `FutureNotesApplication.runtime()` returns one retained engine and creates LocalDocuments, AndroidCipher, AndroidJobHost and PrivateDrafts once (`android/app/src/main/kotlin/com/nativedevps/futurenotes/FutureNotesApplication.kt:12–43`). Activity recreation reattaches (`MainActivity.kt:16–17`) and new shares arrive through both creation and new-intent handling (`:23–24`, `:37–41`). Memory pressure forwards to job/cipher budgeting and Flutter (`FutureNotesApplication.kt:46–63`). These source properties are compatible with the intended Android design; they are not real-host recreation/process-death proof in this review.

**F6.2 — Background limits are deliberately unequal; describe them accurately.** Android's manifest declares dataSync, foreground and notification permissions (`android/app/src/main/AndroidManifest.xml:3–6`, `:66`). `AttachmentJobService` holds the existing owner, uses START_NOT_STICKY, renews a bounded wake lock from active updates, and delegates timeout cancellation (`AttachmentJobService.kt:10–44`). iOS only uses `beginBackgroundTask` (`ios/Runner/MobilePlatform.swift:475–477`); it neither registers nor schedules a `BGProcessingTask`, and `ios/Runner/Info.plist` contains no BGTask identifiers/background mode entry. This is a finite completion window, not Android-style prolonged foreground work. Do not add a new writer/engine or persist passwords to resume jobs. First validate expiration → cancellation → retained recovery; add an iOS scheduled runner only if that separate lifecycle can satisfy the same owner/credential contracts.

Apple documents an expiration handler when remaining background time approaches zero: [UIKit background task](https://developer.apple.com/documentation/uikit/uiapplication/beginbackgroundtask(expirationhandler:)). Android documents the Android-15 dataSync timeout and required `onTimeout` shutdown: [Foreground service timeouts](https://developer.android.com/develop/background-work/services/fgs/timeout). Current-source cancellation handlers establish intent, not completed timeout acceptance.

**F6.3 — iOS live-library updates are incomplete.** `MobileLibraryEvents.listen` returns immediately on non-Android (`lib/core/platform/mobile_library_events.dart:14`). `ProviderNoteFiles.initialize` uses that listener (`provider_note_files.dart:217`), and provider discovery has no periodic scan (`lib/features/dashboard/services/provider_discovery.dart:39–64`). The iOS active notification only uncovers snapshots and announces incoming shares (`MobilePlatform.swift:490`), while dashboard lifecycle handling toggles automatic saving (`lib/features/dashboard/mobile/dashboard_screen.dart:234–238`). Therefore do not claim equivalent live external library reconciliation on iOS. **Fix:** add an iOS presenter/change-hint and resume signal to the existing multiplexer, scoped to the selected bookmark. Reconcile metadata quietly and keep revision checks as write authority; preserve Android cache/discovery behavior and explicit Refresh.

**F6.4 — iOS sharing target wiring is present; signing and execution remain pending.** The current Xcode project contains ShareExtension source, a native target, Runner target dependency and Embed App Extensions phase (`ios/Runner.xcodeproj/project.pbxproj:16–17`, `:44`, `:163–182`, `:298`, `:307`). Both Runner and extension declare the same App Group (`ios/Runner/Runner.entitlements:3`; `ios/ShareExtension/ShareExtension.entitlements:3`); the source copies received files into a protected, backup-excluded App Group inbox, then atomically publishes a receipt (`ios/ShareExtension/ShareViewController.swift:39–124`). The main app claims them through the shared inbox channel (`MobilePlatform.swift:152–239`). Thus “only loose Swift source, no extension target” would be false for this worktree. Developer-team/App Group provisioning and device extension limits are still unvalidated (`ios/ShareExtension/README.md:8–12`). Preserve that distinction.

**F6.5 — iOS progress notifications and cancellation parity are incomplete.** The Swift job channel persists private ledger records and supports in-app cancel/timeout/recovery semantics (`MobilePlatform.swift:441–483`) but does not use UserNotifications or equivalent native per-job notification actions. `MobileJobBinding._takeNotification` is Android-only (`lib/core/platform/mobile_job_binding.dart:114–115`), which is appropriate for its current native adapter. **Fix:** decide whether the iOS product requires native notifications beyond in-app tasks; if yes, implement iOS-specific permitted notification/recovery actions without claiming continuous background progress. Preserve in-app UI and ledger behavior. The shared timeout explanation incorrectly says “Android ended this background-processing window” even on iOS (`mobile_job_binding.dart:61`); make that platform-neutral or adapter-supplied without changing cancellation ownership.

**F6.6 — Cache lifetime/lock contracts are shared; external apps cannot be promised retroactive revocation.** `AttachmentOpenCache` reuses entries after small identity checks with policy-sensitive verification (`lib/core/storage/attachment_open_cache.dart:294–351`), locks its private session and cleans only orphaned owned sessions (`:140–210`). Lock/credential/removal paths invalidate prepared exports, close viewers, evict images, revoke native access, invalidate cache and release source leases (`content_viewmodel.dart:637–660`). iOS open uses UIDocumentInteractionController (`MobilePlatform.swift:385–398`); revoke dismisses that controller, not data already copied by another application. Android similarly revokes its grants rather than deleting other apps' copies. Keep this boundary explicit. Shared viewer lifecycle pauses media without automatically locking (`lib/features/dashboard/mobile/attachment_viewer.dart:470–473`). Native iOS snapshot cover exists (`MobilePlatform.swift:485–490`); validate visually on iPhone/iPad before claiming protected snapshots.

**F6.7 — Private drafts are distinct from published notes.** `MobileDraftBinding` requests Recover/Discard and protected unlock, debounces only new draft identities, writes through native authenticated storage, retains the last good record on failure and flushes on background (`lib/core/platform/mobile_draft_binding.dart:60–118`, `:140–178`, `:209–213`). The Swift adapter uses Keychain and AES.GCM (`MobilePlatform.swift:411–438`); Android has its own PrivateDrafts service. Existing-note recovery rechecks the base revision (`content_viewmodel.dart:7031–7070`). This is source evidence; actual process termination and key-unavailability behavior still require each target. Preserve the separation from library notes and do not auto-publish a recovered new draft.

### Repair order and runtime acceptance gates

1. Do not rewrite the accepted Android ownership/job pipeline while repairing macOS/Linux. Generalize portable behavior through injected capabilities; keep provider APIs, opaque URI/bookmark handling and platform presentation isolated.
2. Correct typed iOS document errors first, then add library-change/resume hints and correct timeout wording as narrow independent work. Keep iOS native job-notification scope explicit. Run an iOS build/signing/device gate before enabling a new adapter.
3. On Android API 24, the LG's API 31, and a current API: activity recreation/orientation, screen-off/wake, foreground/background, notification denial, notification Cancel and timeout, process termination, expired grants, native Save/Share cancellation, cold/warm SEND_MULTIPLE, and all completion/failure cleanup. Observe one owner, per-job progress, cancellation join and no stuck notification. User-visible Hide/Back must not cancel a job.
4. On iOS 13 minimum and a current iPhone/iPad: bookmark persistence/staleness, coordinated local-folder mutation, App Group share from Files/third-party providers, incomplete receipt cancellation, UIKit expiration, app termination/recovery, Keychain availability, cache lock teardown and snapshot cover. Source presence cannot satisfy these gates. Large incoming shares need real extension memory/time measurements; the fixed 120-second provider wait in `ShareViewController.swift:101` is a boundary to exercise, not evidence that all 10 GiB inputs can be received.
5. Compare explicit captured verification policy and payload-pass counters on each real native adapter. Default-off mode must not gain a scan during a new storage/native integration. Preserve the prior Windows/Android artifacts and run affected compatibility gates before replacing either; do not silently extend a successful LG check to iOS, macOS or Linux.

## Review outcome

Shared format/processing contracts are substantially present, and Android contains a distinct native runtime architecture. iOS contains more real integration source than a platform-directory placeholder, including an embedded sharing target, but its typed-error mismatch blocks first library admission; it also has narrower background execution, no native task-progress notification adapter, and no live-library event hook. macOS/Linux cannot inherit mobile-owned import/cache guarantees while still booting the legacy desktop backend. These findings propose bounded fixes and acceptance gates; they do not establish new platform runtime support.
