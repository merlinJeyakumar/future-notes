## Pass 8 — portable tests, audit totals and CI evidence

### Reproducible static recount

The Mac report's **textual counts are reproduced exactly** in this working tree. Definition: enumerate all 124 `test/**/*.dart` files recursively, count regex occurrences in their UTF-8 source, without expanding loops/wrappers or executing tests:

```powershell
$files = Get-ChildItem -LiteralPath test -Recurse -Filter '*.dart' -File
$rows = foreach ($file in $files) {
  $source = Get-Content -LiteralPath $file.FullName -Raw
  [pscustomobject]@{
    Path = $file.FullName
    Skip = [regex]::Matches($source, 'skip:\s*!Platform\.isWindows').Count
    Variant = [regex]::Matches($source,
      'TargetPlatformVariant\.only\(TargetPlatform\.windows\)').Count
    Drive = [regex]::Matches($source, 'D:/').Count
  }
}
$rows | Measure-Object Skip, Variant, Drive -Sum
($rows | Where-Object { $_.Drive -gt 0 }).Count
```

| Measured item | Result | Interpretation |
|---|---:|---|
| `skip: !Platform.isWindows` source expressions | 64 | Host-gating expressions, not exactly 64 registered tests. |
| Windows-only `TargetPlatformVariant.only(...)` expressions | 7 | Flutter UI-target simulations, not native Windows host execution or seven exact test instances. |
| Literal `D:/` occurrences | 32 across 11 files | Portability review candidates, not 32 independently broken tests. |

Why this distinction matters: one skip expression inside the Office format loop registers four native tests (`test/office_preview_service_test.dart:118–145`). One Windows target-variant expression belongs to a reusable scenario registering multiple tests (`test/dashboard_file_drop_test.dart:42–99,156–210`). Setting a Flutter target variant does not change `dart:io`'s host OS or validate native file semantics.

Skip-expression breakdown: Office document widgets 2; Office/PDF service 4; open cache 1; native integration 1; native primitives 1; permanent deletion 7; provider desktop guard 1; recoverable store 21; owner worker 15; Windows file actions 11. Total 64.

Do not mechanically replace all drive strings. Some are pure UI identities (`test/navigation_layout_stability_test.dart:16–46`), while `StorageEnvironment.validation` fixture construction uses host-sensitive paths in settings tests (`test/attachment_performance_settings_test.dart:10–26`, `test/mobile_device_performance_settings_test.dart:10–26`). Use an actual `Directory.systemTemp` run root for filesystem/owned-storage fixtures and preserve explicit Windows path-contract tests. Keep non-I/O UI fixtures simple and platform-neutral; do not introduce real filesystem setup where it does not improve the test.

### What the Mac totals prove

The supplied report records **683 passed / 103 skipped / 192 failed** after a temporary tooltip compatibility adapter. This review did not rerun those commands and has no machine-readable Mac test event stream or exact source/SDK manifest. Consequently these totals are **reported Mac observations**, not locally validated counts or 192 distinct product defects. The 64 source expressions cannot explain all 103 skips one-for-one; loops, optional stress gates and other runtime conditions can change registered outcomes. Likewise a shared constructor can fail many tests: the drop scenario constructs `OwnedAppServices` for every case before exercising UI (`test/dashboard_file_drop_test.dart:47–66`). Classify failures by first failing boundary and retain per-test events before prioritizing independent defects.
