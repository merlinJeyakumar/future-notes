# Compact operation panel and cancellable export preparation — 16 October 2026

## Implementation

The auxiliary operation panel now uses naturally sized, full-width status rows instead of 246 px wide tiles in a fixed 160 px horizontal strip. Cancel/Dismiss sit beside the operation title; phase, progress and byte counts follow directly below. Retry/Remove pending wrap on failure. Multiple jobs stack in a vertically scrollable region capped at the existing maximum height. Collapse animation, lock teardown, job identity and progress subscriptions remain. No new dependencies, storage formats or encryption changes.

The user reported cancellation was stuck and explicitly requested forced termination. PID 33940 was correlated with the candidate launch receipt and exact executable path, stopped and verified absent. No files were removed. The scripted start-time comparison failed because ConvertFrom-Json had already converted the timestamp and the subsequent culture-sensitive Parse failed; the stop record explicitly records that limitation rather than claiming the check passed. Evidence: .validation/compact-operation-stop.json.

Source review found export attachment-source integrity reads occurred before the package cancellation file existed, without passing the existing cancellable-reader token or progress callback. Export now registers a per-job FileReadCancellation before preparation, signals it through the existing cancellation path, reports attachment index/bytes, checks cancellation between awaits and before package creation, and releases the token in finally. Cancellation returns a cancelled result after reader acknowledgement. Package writing/verifying and recoverable publication remain intact. Native file-picker lifetime remains controlled by the native picker; this change does not programmatically dismiss that modal.
